## Docker 构建缺陷与修复

发现 legacy Docker builder 会在 `cargo-deps` 占位源码预编译后，因真实源码保留较旧时间戳而复用占位 `whalelink-server` 可执行文件。其表现为极小的空二进制、启动后正常退出、无健康监听。

`deploy/Dockerfile.server` 已修复：真实源码复制后触碰本地 workspace 源文件，再以固定的已安装 Rust 工具链构建。这会只重编译本地包并保留第三方依赖缓存。服务器验证显示真实协议与 Server 包重新编译完成，最终容器健康检查通过。

## 未完成的 P0 验收

服务器侧控制面已完成。部署者配置的 Caddy 运行在独立 Docker 容器；控制面回环健康，但其 HTTPS:8443 入口返回 502。原因是容器内的 `127.0.0.1:8787` 指向 Caddy 容器自身，不是宿主机控制面。部署者需将上游改为可达的宿主网关，或将 Caddy 与控制面接入同一 Docker 网络后以服务名转发。

在 HTTPS:8443 健康接口返回成功后，执行一次性邀请码的 Windows GUI 兑换、DPAPI 保存、守护进程启动与真实数据面连通验收；在该验收前，不将 GUI 邀请码通路标记为 PASS。
