# 2026-09-19 P0 HTTPS 控制面部署预检

## 目的

在部署 WhaleLink 控制面前，确认指定域名的 DNS、HTTP-01 入口与服务器本机端口状态；检查全程为只读，未变更服务、容器、防火墙或 EasyTier 进程。

## 非敏感结果

| 检查项 | 结果 | 判定 |
| --- | --- | --- |
| 域名 A 记录 | 已解析到目标服务器 | 通过 |
| 公网 HTTP 预检 | 返回 `502 Bad Gateway`，而非目标服务器的 Caddy challenge 响应 | 不通过 |
| 公网 HTTPS 预检 | 尚不能建立受信 TLS 连接 | 预期未就绪 |
| 服务器 Docker / 管理权限 | Docker 与非交互管理权限可用 | 通过 |
| 服务器 80/443 监听 | 未发现本机 80 或 443 的监听进程 | 可供 Caddy 使用，但不证明公网转发正确 |
| 已有服务冲突 | 唯一相关本机 HTTP 服务仅绑定回环地址；未发现 WhaleLink、Nginx 或 Caddy 服务 | 无本机端口冲突 |

## 结论

DNS 条件已满足，但 HTTP-01 仍被目标服务器之外的 502 链路拦截或错误转发。此状态下启动 Caddy 不能保证 Let's Encrypt 能取到 ACME challenge，因此没有进行安装或部署。

继续条件：将该域名的公网 TCP 80 明确转发至该服务器 TCP 80，并允许外部 ACME 校验访问；443 也应转发至服务器 TCP 443，供控制面后续服务。转发完成后，以一次 HTTP-01 预检确认不再返回 502，再开始 Caddy、Docker 控制面和 GUI 邀请码验收。

## 安全边界

本文不记录服务器地址、Relay、网络名、虚拟地址、令牌、邀请码、密钥、用户身份或原始命令输出。
